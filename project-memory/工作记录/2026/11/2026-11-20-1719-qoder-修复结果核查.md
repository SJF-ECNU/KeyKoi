# 独立核查审核缺陷修复结果

## 任务计划书与目标

[[project-memory/任务计划/修复结果核查]]。本次完成步骤 1–5：依据最新修复报告、原始 34 项缺陷和 OpenSpec 清单，复核当前源码与测试，重跑标准 Go 验证和隔离验收，并记录真实失败及未覆盖环境。本轮未修改产品 Go、Shell 或 Swift 源码。

## 结果、改动与验证

### 总结论

不能确认修复报告所称“34 项全部闭环”。按当前源码，24 项主路径符合修复目标，10 项仍有明确缺口：02、04、07、08、11、18、19、22、25、32。这里的“主路径符合”不等于所有并发、原型后端和真实系统环境均已覆盖。

| 编号 | 当前核查结论 |
| --- | --- |
| 02 | [Memory.PutBinding](../../../../internal/store/memory.go#L295) 更新已有 Binding 时不递增 revision，而 Broker 的交付期间改绑检测依赖 revision；SQLite 主路径已处理，原型 Memory 后端仍有缺口。 |
| 04 | [TLS 代理](../../../../internal/tlsproxy/proxy.go#L406) 会在 revision 变化时结束隧道；PostgreSQL/MySQL/MongoDB/Redis 只在认证时取得快照，随后直接 relay，[MongoDB relay](../../../../internal/mongoproxy/proxy.go#L443) 等既有连接没有后续 revision 重校验或断开。 |
| 07 | [中心策略数据](../../../../internal/central/data.go#L10) 没有 PrincipalID，[Broker 版本约束](../../../../internal/broker/broker.go#L63) 只拒绝“本机版本高于中心”；与按实际主体、方式和版本裁定并约束最终取值的规格口径不完全一致。 |
| 08 | [validateSnapshot](../../../../internal/vault/vault.go#L630) 只检查结构和密文非空，未用口令试解根密钥、DEK 或凭证密文；损坏密文仍可能通过恢复前校验，现有测试只覆盖引用不一致。 |
| 11 | [OAuth 回调提交](../../../../internal/oauth/manager.go#L353) 的第二次 Load 与 Commit 不是 CAS，Load 错误被忽略，Commit 后还可能无条件 MarkStatus(active)；管理员在检查/提交窗口停用仍可被覆盖，现有测试未覆盖该竞态。 |
| 18 | [过期清理由 Authorize 触发](../../../../internal/broker/broker.go#L583)，没有定时清扫；网关和 runner 会释放许可，但部分 SSH/签名成功路径及数据库代理未见对应的即时 RevokeLease，短期许可仍可能滞留至后续触发。 |
| 19 | 新建授权会取代旧授权，但 [approve](../../../../internal/daemon/api.go#L563) 可直接复活旧授权，重新形成多个有效授权；存储层没有完整的有效授权唯一约束。 |
| 22 | [runner](../../../../internal/runner/runner.go#L193) 记录 Signal 后仍保存 ProcessState.ExitCode() 的 -1，[shim 退出码映射](../../../../internal/shim/shim.go#L328) 对 -1 返回 0；独立 helper 的信号测试没有覆盖实际 runner→shim 路径。 |
| 25 | [dbproxy Shutdown](../../../../internal/dbproxy/dbproxy.go#L271) 仍裸 wg.Wait()；[PostgreSQL SSLRequest](../../../../internal/dbproxy/upstream.go#L103) 写操作发生在设置读 deadline 之前，关闭和上游握手都存在未完整覆盖的阻塞边界。 |
| 32 | [钥匙串重新登记](../../../../packaging/macos/keykoi-biometric.swift#L192) 的 errSecParam/errSecUnimplemented 回退分支仍先删除正式旧项再写新项；暂存槽可保留新根密钥，但不满足“失败保留原正式项”的严格任务口径。 |

24 项主路径符合的编号为：01、03、05、06、09、10、12、13、14、15、16、17、20、21、23、24、26、27、28、29、30、31、33、34。

另有四项未计入上述 10 项的次级边界观察：12 的 Detach 未核对 ManagedFingerprint，人工后续编辑仍可能被覆盖；13 的存活 socket 探测与删除之间存在 TOCTOU；28 的恢复说明审计在替换后单独追加且错误被忽略；30 的用钥记录只按 binding、allowed 和开始时间前 5 秒匹配，未绑定请求或会话 ID。后续应确认它们是否需纳入独立缺陷。

### 新增真实 MongoDB 失败

本次 Docker 可用，实际运行了 MySQL 8.4.13、MySQL native password 和 MongoDB 7.0.48。Redis/MySQL 均通过，MongoDB 7 项失败。mongosh 2.14.2 报告 `minimum wire version undefined`；[认证前 hello 回复](../../../../internal/mongoproxy/proxy.go#L491) 只默认补 `maxWireVersion=17`，没有补 `minWireVersion`。失败发生在认证前握手，不能把这段结果记为通过或环境跳过。
