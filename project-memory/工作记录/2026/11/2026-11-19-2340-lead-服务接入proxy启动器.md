# 服务进程接入模型 API：proxy 启动模式

## 任务计划书与目标

[[project-memory/任务计划/OpenSpec任务实现]]：回答“Agent 写的服务如何调用模型”，补上只注入会话令牌的启动方式，避免服务进程取得真实 key。

## 结果、改动与验证

- 新增 `keykoi run --mode proxy`：只建立会话并注入 `runtime:session_token`、`runtime:gateway_route`（`http://host:port/gateway/<route>`），**不读取凭证、不申请 runtime_delivery 许可**；退出时关闭会话。
- 新增 `--session-ttl`（默认 12h，上限 24h）与后台会话 TTL 参数；`broker.CreateSessionTTL`、`/v1/sessions` 的 `ttl_seconds`、`ipcclient.CreateSessionTTL` 一并打通。
- Runner 接口调整：会话创建返回会话 ID，运行结束关闭会话；proxy 模式跳过 Resolve，`Result.LeaseID` 为空。
- 验收：`internal/runner` 新增 proxy-only 测试（不取凭证、注入正确 URL、关闭会话）；`keys-matrix.sh` 增至 18 项，新场景用真实 Python 服务经 `keykoi run --mode proxy` 调用网关：服务只拿到 `kks_` 令牌、上游收到真实 key、启动器不持有凭证许可。
- 文档：新增 [[docs/指南/接入模型服务]]（推荐接法、生命周期、错误语义、远程部署边界），更新 [[docs/验收/验收总览]] 与索引。
