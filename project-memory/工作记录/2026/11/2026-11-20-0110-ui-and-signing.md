## 任务计划书

[[project-memory/任务计划/生物识别解锁与授权策略|任务计划书 · 生物识别解锁与授权策略]]，本次推进「签名与看板登录」全部步骤。工作流侧同时更新 [[project-memory/工作流/使用看板与主体授权|使用看板与主体授权]]，该工作流的计划仍是 [[openspec/changes/local-activity-and-subject-grants/design|OpenSpec 设计]]（本次未改）。

## 结果、改动与验证

`keykoi ui [--admin ADDR] [--no-open]` 新增：地址默认取后台 `/v1/status` 的 `admin` 字段（即真实监听地址），也接受 `--admin` 覆盖并规范化 `host:port` / 带 scheme / 带尾斜杠三种写法；令牌按与其他子命令相同的数据目录规则从 `<数据目录>/admin.token` 读取，拼成 `http://<admin>/#token=<token>`。默认模式交给系统浏览器（darwin `open`，子进程输出丢弃），**不把令牌写到 stdout/stderr**；`--no-open` 只打印登录链接与说明，供终端复制与自动化断言。

`web/index.html` 新增 `consumeTokenFromHash()` / `loginFromHash()`：页面加载时读 `location.hash` 的 `token=`、填进登录框并自动 `connect()`，随后立即 `history.replaceState` 清掉 hash；无 `token` 参数时不动 hash，原有行为不变。令牌因此不留在地址栏、历史记录或截图里，也不会随 Referer 外传（页面本就带 `Referrer-Policy: no-referrer`）。

`packaging/macos/sign-biometric.sh` 新增：`security find-identity -v -p codesigning` 按 Developer ID Application → Apple Development → Apple Distribution → Mac Developer 优先级取身份，从证书 OU 取团队 ID，渲染 `keykoi-biometric.entitlements` 里的 `TEAMID` 前缀，然后 `codesign --force --options runtime --entitlements <渲染后> --sign <身份>`，再用 `codesign -d --entitlements :-` 与 `codesign --verify --strict` 校验并输出是否含 `keychain-access-groups`。找不到身份时打印 Xcode 登录、创建团队、Keychain Sharing 三步指引并退出码 2。`install.sh` 在 `KEYKOI_SIGN_BIOMETRIC=1` 时可选调用，签名日志写 `<prefix>/data/sign-biometric.log`，失败不中断安装。

签名脚本额外做了两件必要的事，并因此改了交付形态：

1. 保留签名前的副本，`codesign --verify` 或 `keychain-access-groups` 校验不通过时恢复并退出码 4。
2. 签名后跑一次 `available` 启动探测。实测本机 `keychain-access-groups` 是受限权限：没有描述文件授权时，裸二进制一启动就被 AMFI 杀死（`exit=137`）。此时默认回滚到签名前的产物、把签名结果留在 `<helper>.signed`，避免装上一个连 `available` 都跑不起来的助手；`--keep-signed` 可保留现场。

本机签名环境（真实结果）：`xcode-select -p` = `/Applications/Xcode.app/Contents/Developer`，`security find-identity -v -p codesigning` 有 1 个有效身份，类别 Apple Development，团队 `977QNJU6V6`。签名后 `entitlements_keychain_access_groups=yes`、`codesign_verify=ok`、`signature_team=977QNJU6V6`、`launch_probe=blocked-by-amfi`、`deploy=reverted`；恢复后的 `available` 仍返回 0。另在临时 prefix 跑 `KEYKOI_SIGN_BIOMETRIC=1 install.sh --no-load` 验证钩子整链可用（结束后已清理临时 prefix 与测试用 LaunchAgent）。

验证：`go build ./...` 通过；`bash tests/acceptance/ui-login.sh` 30/30（`docs/验收/artifacts/ui-login/result.json`）；`bash tests/acceptance/biometric-signing.sh` 21/21（`docs/验收/artifacts/biometric-signing/result.json`）。`ui-login.sh` 覆盖默认地址、`--admin` 覆盖与规范化、浏览器模式不泄漏令牌、后台缺失时的明确报错、curl 取页面确认 hash 处理逻辑、node 无头执行 `consumeTokenFromHash`（解析、清除到裸 path、百分号解码、无 token 时不碰 history）。`biometric-signing.sh` 覆盖环境记录、真实身份分支（签名 + entitlements + 独立复核 + 启动探测 + 回滚后 `available`）、PATH 替身模拟无身份分支（退出码 2 与提示文本）、`install.sh` 钩子静态检查。

决策依据：任务要求「不打印 token 到 stdout/stderr」与「`--no-open` 输出 URL 且 URL 含 token」在同一行里冲突，取「令牌只随 `--no-open` 的登录链接出现一次、默认模式不写令牌、也从不单独打印令牌」的折中，并在 `ui-login.sh` 里分别断言这两个方向。

## 剩余工作与下一步
