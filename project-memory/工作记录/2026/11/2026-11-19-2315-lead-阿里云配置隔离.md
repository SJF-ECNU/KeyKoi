# 阿里云 CLI 配置文件优先级与 shim 隔离

## 任务计划书与目标

[[project-memory/任务计划/OpenSpec任务实现]]：修正无感入口对工具自带配置文件的处理。用户指出阿里云 CLI 有独立配置文件，实测确认该文件会覆盖环境变量。

## 结果、改动与验证

- 实测 aliyun-cli 3.5.3 优先级：`~/.aliyun/config.json` 的 AK profile **优先于** `ALIBABA_CLOUD_*` 环境变量；两者同时存在时上游收到的是配置文件里的 AccessKeyId。`ALIBABA_CLOUD_CONFIG_FILE` 不被该版本识别；`--config-path <不存在路径>` 可让 CLI 只使用环境变量，且不会创建文件。
- 另测得：`ALIBABA_CLOUD_REGION_ID` 生效；配置文件 profile 若为 `mode: AK` 会丢弃 SecurityToken，缺失配置路径时 STS 组合正常。
- shim 新增 `--prepend-arg`：在需要凭证的调用前插入固定参数（验收用 `--config-path <数据目录>/shims/<name>.no-config.json`，该路径保持不存在），从而隔离工具的明文配置。用户若自传同名前缀参数，shim 拒绝并提示改用 `keykoi run`，避免静默绕过。
- `keykoi shim install` 检测到 aliyun 明文 profile 时输出警告；`configure`、`plugin`、`upgrade` 等本地命令仍走原生路径，不注入凭证。
- 验收：`shim-aliyun.sh` 扩到 28 项全过（旧明文配置被忽略且原文件不变、托管路径不落盘、静态 AK/SK 与 STS 两种组合、用户自传 `--config-path` 被拒、`configure list` 读真实配置）；`tool-aliyun.sh` 12/12（改为显式 `--config-path` 隔离）；`go test ./...` 通过。
