# 用真实阿里云 CLI 验证运行时交付

## 任务计划书与目标

[[project-memory/任务计划/OpenSpec任务实现]]，补充步骤 10 的真实工具证据：验证 aliyun-cli 3.5.3 能否通过 KeyKoi 取得凭证并完成认证。

## 结果、改动与验证

- 本机安装 aliyun-cli 3.5.3（Homebrew）。确认其凭证来源支持环境变量 `ALIBABA_CLOUD_ACCESS_KEY_ID` / `ALIBABA_CLOUD_ACCESS_KEY_SECRET` / `ALIBABA_CLOUD_SECURITY_TOKEN`，`--endpoint` 只接受裸 host[:port]，默认 HTTPS。
- 新增受控阿里云 RPC 响应到 `tests/fixtures/mockupstream`：按 `Action` 返回 XML，新增 `--expect-query K=V` 与 `access_key_seen`/`signature_seen`/`security_token_seen`/`query_matched` 统计；不记录秘密值。
- 新增 `tests/acceptance/tool-aliyun.sh`：真实 `aliyun` 经 `keykoi run` 注入环境变量，访问受控 HTTPS 上游（自签测试证书），12 项检查全过（工具退出码、响应结构、AccessKeyId 值匹配、HMAC-SHA1 签名存在、SecurityToken 到达、中介令牌未泄露、许可撤销与进程树清理、无明文落盘、proxy-only 越模式拒绝、锁定拒绝）。
- 结论：阿里云 CLI 的签名在查询串中，Header 网关无法替换认证，正确接入模式为 `runtime_delivery`；真实账号可按验收总览中的命令录入并使用。证据：`docs/验收/artifacts/tool-aliyun/result.json`。
