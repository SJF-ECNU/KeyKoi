## 任务计划书

[[project-memory/任务计划/生物识别解锁与授权策略|任务计划书 · 生物识别解锁与授权策略]]，推进本次新增的「已签名 .app 包装」步骤表；工作流 [[project-memory/工作流/生物识别解锁与授权策略|生物识别解锁与授权策略]] 同步更新当前状态与下一步。

## 结果、改动与验证

**构建方式：Xcode 工程 + `xcodebuild -allowProvisioningUpdates` 自动签名。** 本机没有 `xcodegen`（`which xcodegen` 为空），所以工程文件由 `packaging/macos/biometric-app/Tools/generate-xcodeproj.py` 确定性生成：固定 24 位对象 ID、`objectVersion = 56`、单个 `PBXProject` + 单个应用 target，并生成共享 scheme；同目录保留 `project.yml` 作为 xcodegen 的对照描述。`xcodebuild -list` 能识别 target 与 scheme。

目标类型是 macOS application，靠 `EXECUTABLE_NAME = keykoi-biometric` 让产物落在 `KeyKoi Biometric.app/Contents/MacOS/keykoi-biometric`（`PRODUCT_NAME` 仍是 `KeyKoi Biometric`，所以包名不变）。`App/Info.plist` 设 `LSUIElement`、`CFBundleExecutable=keykoi-biometric`、`CFBundleIdentifier=$(PRODUCT_BUNDLE_IDENTIFIER)`；`App/KeyKoiBiometric.entitlements` 设 `keychain-access-groups = $(AppIdentifierPrefix)com.keykoi.biometric`；target 设置 `ENABLE_APP_SANDBOX=NO`、`ENABLE_HARDENED_RUNTIME=YES`、`CODE_SIGN_STYLE=Automatic`、`DEVELOPMENT_TEAM=977QNJU6V6`。脚本里没有任何团队/身份硬编码到源码之外的地方，团队可用 `--team` 覆盖。

`packaging/macos/build-biometric-app.sh` 新增：缺工程时先跑生成器，然后 `xcodebuild -project ... -scheme KeyKoiBiometric -configuration Release -derivedDataPath ... -allowProvisioningUpdates DEVELOPMENT_TEAM=977QNJU6V6 CODE_SIGN_STYLE=Automatic build`，日志写 `<derived-data>/xcodebuild.log`。成功后校验 `codesign --verify --strict`、`codesign -d --entitlements :-` 里的 `keychain-access-groups` 与签名团队前缀一致、`Contents/embedded.provisionprofile` 经 `security cms -D` 解出的 Entitlements 含该组且团队匹配、`Info.plist` 的 `LSUIElement`，最后执行一次 `available` 作为启动探测，输出 `launch_probe=ok|no-biometry|unavailable|killed-on-launch|failed`。结束时把 `KEYKOI_BIOMETRIC_HELPER=<绝对路径>` 打到 stdout（`--print-path` 只输出路径，`--status-file` 写 key=value 供验收读取，`--install-dir` 用 `ditto` 复制到稳定位置）。退出码：0 通过 / 2 需要人工（未登录 Apple ID、无 Keychain Sharing、无描述文件、网络）/ 3 构建失败 / 4 校验失败 / 5 环境不可用；失败按日志分类成 `apple-id`、`keychain-sharing`、`profile`、`network`，每类打印各自的人工步骤。

**真实结果（本机）：** Xcode 27.1，`xcode-select -p` = `/Applications/Xcode.app/Contents/Developer`，`security find-identity -v -p codesigning` 有 1 个 Apple Development 身份，团队 `977QNJU6V6`。`-allowProvisioningUpdates` 让 Xcode 自动注册 App ID 并签发了 `Mac Team Provisioning Profile: com.keykoi.biometric`（UUID `c482a923-4ff6-4ec8-adca-5e08180744e5`，7 天有效期；个人团队也支持该能力，实测无需手工到 developer.apple.com 勾选）。签名里 `keychain-access-groups = 977QNJU6V6.com.keykoi.biometric`，描述文件授权 `977QNJU6V6.*`，`TeamIdentifier=977QNJU6V6`，`codesign_verify=ok`，`launch_probe=ok`，`available` 退出码 0。也就是说助手现在真的能启动：`packaging/macos/sign-biometric.sh` 里裸二进制被 AMFI 杀死的那个现象，在 `.app` 下不再出现。

**真实 Keychain 往返：** `store`（32 字节随机值）退出码 0（此前裸二进制是 `errSecMissingEntitlement -34018`），`load` 取回同一值，`delete` 幂等清理。`load` 会触发一次系统生物识别验证，本机多次实测在 5~25 秒内返回正确密钥，但没有出现需要我点按的指纹对话框（可能由近端设备或系统已授权的验证窗口满足）；因此在会弹框的机器上，用户手势仍是人工步骤，验收脚本把这种情况记 MANUAL 而不是 FAIL。

**keykoid / vault 接入：** 新增 `internal/vault/biometric_path.go` 的 `ResolveHelperPath` / `NormalizeHelperPath`：显式参数 → `KEYKOI_BIOMETRIC_HELPER` → keykoi/keykoid 同目录的裸二进制或 `KeyKoi Biometric.app` → `PATH`；环境变量可以写裸可执行文件、`.app` 包或包内 `Contents/MacOS` 三种形态，后两种归一化成包内 `keykoi-biometric`。`cmd/keykoid/main.go` 删掉私有 `resolveBiometricHelper` 改调它，默认路径语义不变。`keykoi-biometric.swift` 的入口从顶层 `exit(run())` 改成 `@main enum KeyKoiBiometricMain`：app 目标以 `-parse-as-library` 编译，顶层语句（哪怕在 `#if` 的未激活分支里）都会报 “Expressions are not allowed at the top level”；`build-biometric.sh` 同步加 `-parse-as-library`，裸二进制契约不变。

顺带修掉一个挡路的旧 bug：`keykoi --data-dir` 只改数据目录、不改 socket，导致 `keykoi --data-dir X ...` 仍连默认 socket（`cmd/keykoi/main.go`，现在 `g.socket = osruntime.SocketPath(g.dataDir)`，显式 `--socket` 仍可覆盖）。

**验证：**
- `bash tests/acceptance/biometric-app.sh` → 31/31，exit 0，`docs/验收/artifacts/biometric-app/result.json`。断言覆盖：构建退出码、`launch_probe=ok`、`entitlements_keychain_access_groups=yes`、`codesign_verify=ok`、`KEYKOI_BIOMETRIC_HELPER=` 输出、包名/可执行文件位置/`embedded.provisionprofile`、`Info.plist` 的 bundle id 与 `LSUIElement`、签名团队、描述文件的组与团队、`available`、`store/load` 同值往返与清理、keykoid 经环境变量启动并让 `keykoi init`/`vault enroll-biometric`/`auth status available=true` 全部成功、`internal/vault` 路径解析单测。
- 失败分类用 `PATH` 替身（假的 `xcodebuild` 打印对应报错并 exit 65）分别命中 `apple-id` / `keychain-sharing` / `profile`，三次都退出码 3 且打印对应人工步骤。
- `go build ./...`、`go test ./...` 全绿（`internal/vault` 新增 6 个路径解析用例）。
- 回归：`bash tests/acceptance/biometric-auth.sh` 65/65、`bash tests/acceptance/biometric-signing.sh` 21/21 仍全部通过（两个脚本按设计会重写各自的 `result.json`，检查项与结果不变）。

**清理与边界：** 验收与手工测试都使用一次性 Keychain 账号（`keykoi-acceptance-*`、`keykoi-biometric-selftest*`），结束时 `delete` 清理；清理时还调过一次 `delete --account keykoi-root`，该账号在本机此前从未成功写入（历史记录里 `store` 一直返回 -34018），属于幂等空操作。没有改动真实密钥库数据目录、没有触碰其他 acceptance 脚本或 openspec。`packaging/macos/biometric-app/build/` 是 DerivedData，已由 `.gitignore` 排除。
