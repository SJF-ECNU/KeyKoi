# 全项目代码与功能审核

关联工作流 [[project-memory/工作流/全项目代码与功能审核]]。

目标是按当前本机源码给出按严重度排列、可定位的功能与安全缺陷。范围包含 Go 命令和运行包、Web 控制台、适配器、macOS 安装及 Touch ID 源码、测试和验收脚本。生成的构建文件、个人配置、运行中凭证库与外部服务不参与审核。

1. 用 CodeGraph 再结合源码确认入口、边界及调用者。
2. 对权限和储存、代理协议、CLI 和界面并行做静态审核，并核查每个发现的条件和反例。
3. 在本机执行标准测试和隔离的现有功能验收，记录结果、覆盖范围和剩余不确定性。

## 审核结论

P1 表示应优先修复的权限失效、凭证去向错误、数据丢失或主要功能中断。P2 表示条件受限的缺陷或能稳定影响功能的回归。安全结论以源码控制链为证据，实际执行限于本机隔离测试与测试上游。

### P1 优先

| 编号 | 缺陷与影响 | 修复方向与源码 |
| --- | --- | --- |
| 01 | **仅有签名权限可以取得原始凭证。** Unix IPC 通用解析接口接受签名模式，并返回整组解密字段。具备本机访问权限、签名授权且完成相应验证的调用方，可拿到 SSH 私钥或 AccessKey Secret。 | 将签名操作留在受信服务内部，通用解析只接受原值交付许可。SSH Agent 通过签名接口返回结果。[通用解析](../../internal/daemon/api.go#L182) · [SSH 材料读取](../../internal/ssha/ipc.go#L37) |
| 02 | **撤销与正在等待的验证有竞态。** Broker 在 Touch ID 前读取许可、会话和版本。等待期间撤销、停用或轮换，验证返回后仍可能完成旧的用钥决定。 | 交付前重新核对会话、授权、绑定及凭证版本，验证缓存只写入当前有效的授权状态。[授权与验证](../../internal/broker/broker.go#L356) · [最终材料读取](../../internal/broker/broker.go#L423) |
| 03 | **主密钥库锁定后，独立 TLS 代理仍可能继续用钥。** 代理自行解锁并建立独立 Broker，该 Broker 没有主服务的逐次验证与中心校验；代理连接共享启动会话。共享数据库中的授权状态仍会被重新查询。 | 把代理的用钥决定交给主服务，统一应用锁定、验证和中心策略。[TLS 代理启动](../../cmd/keykoi/tlsproxy_cmd.go#L88) · [代理授权](../../internal/tlsproxy/proxy.go#L338) |
| 04 | **改绑时可能把新凭证发到旧目标。** TLS 隧道保留建连时的目标。四种数据库代理也会分开读取目标和凭证。绑定更新遇到在途请求时，目标和密钥可能来自不同版本。 | 让转发使用同一次授权返回的绑定与版本，既有连接在绑定变更时重校验或结束。[TLS](../../internal/tlsproxy/proxy.go#L307) · [PostgreSQL](../../internal/dbproxy/dbproxy.go#L497) · [MySQL](../../internal/mysqlproxy/proxy.go#L491) · [MongoDB](../../internal/mongoproxy/proxy.go#L473) · [Redis](../../internal/redisproxy/proxy.go#L416) |
| 05 | **部分数据库代理的上游连接缺少可验证的安全传输。** Redis 上游直接用 TCP 发送 AUTH。MySQL 的完整认证可使用上游临时返回但未经验证的 RSA 公钥。连接跨越不可信网络时可能暴露凭证。 | 对上游启用并验证 TLS，或以受信配置明确登记其他安全传输。[Redis 上游认证](../../internal/redisproxy/proxy.go#L529) · [MySQL 上游握手](../../internal/mysqlproxy/upstream.go#L158) |
| 06 | **中心设备注册凭据等同于管理员凭据。** 设备注册和策略写入、撤销都使用同一个可反复使用的秘密。此外，跨机器以中心内置 HTTP 监听直接部署时，链路上无 TLS。 | 分离设备注册和管理员权限，远程部署强制受保护传输。[设备注册](../../internal/central/server.go#L161) · [管理操作](../../internal/central/server.go#L333) · [服务监听](../../cmd/keykoi-central/main.go#L37) |
| 07 | **中心许可的用钥方式与凭证版本未被端到端约束。** 客户端统一申请并按绑定缓存代理许可，Broker 最终按本机授权模式交付本机当前版本。正确的中心签名或原值策略可能拒绝正常调用，中心代理许可也无法限制本机交付模式。 | 用实际主体、方式和版本申请许可，并以中心许可约束最终取值。[中心校验](../../internal/central/client.go#L149) · [Broker 取值](../../internal/broker/broker.go#L386) |
| 08 | **备份和恢复可能损坏现有密钥库。** 备份可截断已有目标文件，目标指向运行库时会破坏 SQLite。恢复检查外层格式后便替换现有记录，未先核对当前版本引用或确认可解密。 | 禁止备份覆盖数据库，原子地写出备份，先完整校验恢复对象再提交替换。[备份写入](../../internal/vault/vault.go#L462) · [恢复入口](../../internal/vault/vault.go#L474) |
| 09 | **恢复另一套空库后，旧 Touch ID 登记可能解锁错误的根密钥。** 空库没有密文可校验，代码接受长度正确的根密钥。旧登记取回的根密钥可能被用于新导入凭证，之后用恢复库的主密码解锁便无法读取这些新凭证。 | 为每个密钥库保存独立的根密钥校验依据，恢复后重新匹配系统登记。[生物识别根密钥校验](../../internal/vault/biometric_ops.go#L18) · [恢复后的状态](../../internal/vault/vault.go#L491) |
| 10 | **OAuth 令牌交换允许不安全的传输或跨站跳转。** 通用 OAuth 服务接受 HTTP，并使用默认跳转策略。提供方在跳转时保留 POST，可使敏感表单离开原令牌端点。HTTP 网关内置令牌交换已有独立的禁止跳转策略。 | 默认要求受验证的 HTTPS，令牌交换严格限制目标和跳转，回环测试单独处理。[通用 OAuth HTTP 客户端](../../internal/oauth/oauth.go#L166) · [令牌请求](../../internal/oauth/oauth.go#L293) |
| 11 | **在途 OAuth 登录可覆盖管理员随后执行的停用。** 回调提交后会把非活跃记录转为活跃。等待回调期间停用凭证时，先前的登录可能把它重新启用。并行手工轮换也缺少预期版本检查。 | 对回调绑定发起时的版本和状态，保留管理员更新的停用状态。[回调](../../internal/oauth/manager.go#L194) · [重新启用逻辑](../../internal/oauth/manager.go#L353) |
| 12 | **AWS 接入备份可能复制明文，撤销接入可能覆盖其他配置。** 备份保存整份配置，可能把其他账号的明文复制到新文件。撤销时恢复整份旧配置，再删受管字段，可能丢掉后来的其他编辑以及接入前已有的助手设置。 | 只还原本次管理的字段，独立保存原始字段值，对含秘密的恢复材料做加密。[配置备份](../../internal/integration/manager.go#L292) · [撤销接入](../../internal/integration/manager.go#L390) |
| 13 | **启动第二实例或配置 SSH Agent 时可能替换运行中的后台套接字。** Unix 监听无条件先删除旧路径。SSH CLI 还可能将后台的全局套接字参数读成自己的监听路径。后台进程仍在运行，原客户端却失去连接。 | 分离后台与 Agent 参数，确认路径对应空闲或失效的 socket 再处理。[Unix 监听](../../internal/osruntime/ipc.go#L15) · [SSH CLI](../../cmd/keykoi/sshagent_cmd.go#L36) |
| 14 | **Redis 在认证前可以无界地解析请求。** 未校验长度和嵌套深度的解析会在认证前分配内存。能连到监听器的进程可能使代理失去服务能力。 | 给认证前的输入和消息解析设置与正常握手匹配的上限。[认证入口](../../internal/redisproxy/proxy.go#L325) · [RESP 解析](../../internal/redisproxy/resp.go#L107) |
| 15 | **macOS 新装的 shim 仍可能找错配置目录。** 普通 CLI 在安装目录下找 `data`，shim 分支在这之前启动，仍使用旧默认目录。安装后直接启动 `gh`、`aliyun` 等 shim 可能落入 KeyKoi 的参数处理。当前这台 Mac 已有此前接入时加的兼容链接。 | 让 shim 与主 CLI 共用数据目录解析。[CLI 启动](../../cmd/keykoi/main.go#L25) · [shim 启动](../../internal/shim/shim.go#L218) · [安装数据目录](../../packaging/macos/install.sh#L108) |

### P2 其他确认缺陷

| 编号 | 缺陷与影响 | 修复方向与源码 |
| --- | --- | --- |
| 16 | **凭证轮换分三次写库。** 中断可能留下已插入但未启用的版本，下一次操作撞上相同版本号。版本启用和到期时间也可能不同步。 | 在一个事务内插入版本、切换当前版本并更新到期时间。[轮换流程](../../internal/vault/vault.go#L269) · [SQLite 更新](../../internal/store/sqlite.go#L465) |
| 17 | **会话级预验证可被跨会话复用。** 管理员显式验证未提供会话 ID 时，`once` 缓存把空值当通配并没有自己的到期规则。 | `once` 必须对应具体会话，或把无会话预验证变成明确的一次性交换。[缓存匹配](../../internal/broker/authn.go#L195) · [缓存写入](../../internal/broker/authn.go#L239) |
| 18 | **已关闭和过期的会话持续占用内存。** 会话关闭只改变状态，过期查询只返回错误。HTTP 代理为每次用钥创建许可，通常等到会话关闭才清理。 | 及时删除结束的记录，为短期许可补齐正常请求结束及过期的清理。[会话读取](../../internal/broker/broker.go#L211) · [会话关闭](../../internal/broker/broker.go#L260) · [许可创建](../../internal/broker/broker.go#L408) |
| 19 | **重复路由与重复许可的选择不明确。** 数据库未保证路由唯一。多份相同主体、绑定和用钥方式的许可都可以有效，撤销一份或新增更严格策略可能没有预期效果。 | 对有效路由和有效许可定义唯一的选择规则，并由服务端约束。[绑定表](../../internal/store/sqlite.go#L65) · [创建授权](../../internal/daemon/api.go#L470) · [查找授权](../../internal/broker/broker.go#L474) |
| 20 | **SSH Agent 会在会话过期后继续监听但无法签名，也可能遗漏继承的密钥。** 启动时只创建一次会话，后台重启或默认期限过去后无续期。枚举只看直接权限，与 Broker 的账户权限继承规则不同。 | 重建失效会话，让枚举与用钥共用有效权限规则。[Agent 会话](../../cmd/keykoi/sshagent_cmd.go#L61) · [密钥枚举](../../internal/daemon/handlers_ssh.go#L35) |
| 21 | **Git 与 AWS 助手在 macOS 含空格的默认安装路径下可能启动失败。** 两处都把可执行文件路径直接拼入工具解析的命令字符串。 | 按各工具命令语法引用可执行文件路径与参数。[Git helper](../../cmd/keykoi/git_cmd.go#L58) · [AWS credential_process](../../internal/integration/manager.go#L221) |
| 22 | **包装命令可能吃掉子命令参数，交互工具可能挂起。** 全局参数扫描越过 `--`。运行器给子进程另开进程组但未移交前台终端。shim 还会把某些被信号终止的情况返回为成功。 | 保留 `--` 后全部参数，正确处理前台进程、信号和退出码。[参数解析](../../cmd/keykoi/main.go#L43) · [进程组](../../internal/runner/runner.go#L118) · [退出码](../../internal/shim/shim.go#L331) |
| 23 | **MySQL TLS 握手可能丢掉已经缓冲的数据。** 代理读到 SSLRequest 后直接用原连接建立 TLS，原缓冲区预读到的握手数据不会交给 TLS。本机全量竞态测试出现 EOF，随后单测两次独立复跑通过。 | TLS 切换时保留缓冲区中尚未消费的字节。[切换 TLS](../../internal/mysqlproxy/proxy.go#L352) · [现有握手测试](../../internal/mysqlproxy/proxy_test.go#L340) |
| 24 | **Redis 声明 RESP3，但上游仍使用 RESP2。** 代理完成虚拟协商后直接转发，上游只执行认证。依赖 RESP3 类型的客户端会出现解析或语义异常。 | 双向协商同一协议，或仅宣告真正支持的版本。[前端协议](../../internal/redisproxy/proxy.go#L309) · [上游握手](../../internal/redisproxy/proxy.go#L529) |
| 25 | **数据库代理退出可能被空闲连接无限拖住。** 关闭只处理监听器，再等待现存连接自行结束。PostgreSQL 上游认证读取还缺乏独立的完整超时。 | 关闭时限时排空并取消活跃连接，给上游握手设截止时间。[退出入口](../../cmd/keykoi/dbproxy_cmd.go#L206) · [等待连接](../../internal/dbproxy/dbproxy.go#L267) · [上游认证](../../internal/dbproxy/upstream.go#L184) |
| 26 | **中心重启后在线客户端可能一直拒绝用钥，直到旧许可快过期。** 服务端拒绝旧授权代次，客户端仅在另一种失效状态上立即刷新。 | 明确区分可安全重新申请的旧代次与真正撤销，再做一次有界重试。[服务端代次检查](../../internal/central/server.go#L276) · [客户端重试](../../internal/central/client.go#L179) |
| 27 | **普通授权失败会变成 Git 的 HTTP 500。** 网关遗漏身份验证错误的状态映射。当前 Git HTTPS 验收在第一次代理用钥时记录 `AUTH_UNAVAILABLE`，客户端收到 500。AWS 运行时验收的旧脚本也没有准备默认会话策略要求的验证。 | 让网关传达可处理的验证状态，用当前授权策略更新隔离验收。[HTTP 状态映射](../../internal/gateway/gateway.go#L423) · [Git 验收](../../tests/acceptance/git-no-plaintext.sh#L71) · [AWS 验收](../../tests/acceptance/p1-runtime.sh#L72) |
| 28 | **密钥库恢复会清空审计，而且旧接入记录会留在新库旁。** 加密快照没有审计或接入记录；恢复清除审计但继续显示原来的接入记录。 | 明确备份与恢复的审计保留策略，对接入状态做同步或重新核对。[快照字段](../../internal/vault/vault.go#L415) · [恢复清理](../../internal/store/sqlite.go#L318) |
| 29 | **CLI 凭证创建和轮换通过参数接收秘密字段。** 这会让正常的终端输入进入历史，也可能在子进程运行期间出现在进程参数中。 | 提供隐藏输入、stdin 或当前的受控 Web 表单路径，并更新 CLI 示例。[凭证创建](../../cmd/keykoi/manage.go#L96) · [凭证轮换](../../cmd/keykoi/manage.go#L122) |
| 30 | **AWS 环境适配器的验证可能误用主机已有凭证。** 接入登记写入元数据，验证直接运行程序时未按清单经 KeyKoi 解析和注入凭证。 | 用适配器实际运行路径验收，并核对本次请求的用钥记录。[接入应用](../../internal/integration/manager.go#L242) · [验证](../../internal/integration/manager.go#L352) |

| 34 | **诊断测量客户端跟随跨来源跳转时可能携带中介会话请求头。** 仅在上游返回跳转且使用该测量入口时触发。 | 禁止测量请求携带认证跨来源跳转。[测量请求](../../cmd/keykoi/helper_measure.go#L104) · [网关响应头](../../internal/gateway/gateway.go#L165) |

### 实测与覆盖

| 检查 | 结果 |
| --- | --- |
| `go test ./...` | 通过。 |
| `go test -race -cover ./...` | MySQL 客户端 TLS 用例出现握手 EOF，全量命令失败；该用例单独开启竞态检查重跑两次通过。没有将 EOF 归为 Go 数据竞争报警。 |
| 一键登录现有验收 | 30/30。 |
| Git HTTPS 与 AWS 运行时现有验收 | 两项失败。Git 克隆退出 128，隔离库记录验证不可用；AWS 首次助手调用退出并记录验证不可用。核对的是当前源码和隔离实例。 |
| Shell、Python、内嵌 JS、Swift | 语法检查通过。Swift 使用项目构建脚本规定的 `-parse-as-library`。常见明文凭证和 PEM 标记检查只命中预期的无效密钥测试字面量。 |
