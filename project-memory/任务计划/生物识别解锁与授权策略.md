# 任务计划书 · 生物识别解锁与授权策略

对应工作流：[[project-memory/工作流/生物识别解锁与授权策略]]。

## 目标、范围与方案

交付 Touch ID 解锁密钥库与可配置的 Grant 授权策略，并把验证方式写入审计。

- 根密钥不直接用指纹加密：根密钥仍是 32 字节随机值，存入 macOS Keychain，条目 ACL 使用 `biometryCurrentSet`；Touch ID 通过后由系统把根密钥交给 keykoid。
- Swift 助手 `packaging/macos/keykoi-biometric.swift` 调用 LocalAuthentication + Security，子命令 `store/load/available/delete`，退出码 0/2/3/4 分别表示成功、无生物识别、用户取消、不可用或非 GUI。
- `vault.UnlockWithRootKey` / `RootKeyForEnrollment` 提供根密钥解锁与登记入口；`Init` 后自动尝试登记，失败不阻塞。
- `model.AuthPolicy` 解析 `once|window:N|per_use|permanent`；`Grant.AuthRequirement` 落库（SQLite `ALTER TABLE` 迁移，Memory store 同步）。
- `broker.Authenticator` + `AuthCache` 只驻留内存，锁库、撤销、轮换、重启清空；Broker 在放行前执行策略。
- 失败语义：`AUTH_REQUIRED`（取消/失败，HTTP 401）与 `AUTH_UNAVAILABLE`（无生物识别/非 GUI/未登记，HTTP 503）；无生物识别时回退一次性主密码证明，回退不可用则明确拒绝。
- 文件范围：`packaging/macos/**`、`internal/{vault,broker,store,daemon}/**`、`cmd/keykoi/**`、`web/index.html`、`tests/acceptance/biometric-auth.sh`、`tests/fixtures/**`、`docs/验收/验收总览.md`（仅新增行）。不改 `openspec/tasks.md` 与其他 acceptance。

完成条件：`tests/acceptance/biometric-auth.sh` 全绿并写出 `docs/验收/artifacts/biometric-auth/result.json`；`go test ./internal/{vault,broker,store,daemon}` 与 `go build ./...` 通过。

当前步骤：部署与描述文件续签已完成。`install-biometric-app.sh` 读 `ExpirationDate`、临期才重建、部署后复校签名与 `keychain-access-groups`；`install-biometric-renew.sh` 装了每周一次的 LaunchAgent（本机已加载，`next fire = 2026-11-22 03:17`，早于描述文件 `2026-11-26T17:13:46Z` 到期）；`install.sh` 默认部署 `.app` 并把 `KEYKOI_BIOMETRIC_HELPER` 写进 keykoid 的 launchd 环境。验收 `biometric-renewal.sh` 86/86。签名 `.app` 包装仍保持原状，真实 Keychain 的 `store/load` 是自动断言（`biometric-app.sh` 31/31）。`build-biometric-app.sh` 在本机用 Xcode 已登录的 Apple ID（Personal Team `977QNJU6V6`）自动生成 `Mac Team Provisioning Profile: com.keykoi.biometric`，签名里 `keychain-access-groups = 977QNJU6V6.com.keykoi.biometric`，描述文件授权 `977QNJU6V6.*`，`launch_probe=ok`。

下一步（人工）：在装有 Touch ID 且会弹指纹框的机器上人工确认一次 `keykoi vault enroll-biometric` → `keykoi unlock --biometric`，把「用户手势」这一条从 manual 拿掉。另一件（需要重启服务）：用新的 `install.sh` 重跑一次安装，让运行中的 keykoid 从 plist 读 `KEYKOI_BIOMETRIC_HELPER` 指向 `.app` 内助手；本次只改了脚本，没有重启用户已加载的 `com.keykoi.keykoid`。

未决项：`keychain-access-groups` 只在 `.app` + 描述文件下被系统接受，裸二进制分支（`sign-biometric.sh`）继续作为回滚与诊断路径保留；自动签名依赖 Xcode 登录与网络，离线环境会落到 `failure_class=network`（续签日志会写 `manual:` 与四步人工指引）。描述文件仍在有效期内时 Xcode 会复用旧文件，重建不会提前推进 `ExpirationDate`，只有过期/缺失才拿到新的 7 天窗口——所以 7 天到期这件事靠「每周检查 + 临期重建」兜住，而不是每次重建都刷新时间；要真正降频只有付费开发者账号（1 年）方案。
