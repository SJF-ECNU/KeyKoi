# 钥鲤 KeyKoi项目记忆

项目记忆基于仓库内 Markdown，不依赖 Obsidian；可直接用智能体或文本编辑器读取和维护。如需图谱可视化，可选用 Obsidian，并将仓库根目录作为 Vault 打开，不要只打开 `project-memory/` 子目录。本页、文档图谱和项目本地 Skill 跟随当前 Git checkout；切换分支或提交后从当前版本重新接管。被引用的项目文件仍是权威来源。

## 接管工作

1. 确认当前目录；已纳入 Git 时核对分支或提交，切换后重新加载上下文。
2. 阅读 [[project-memory/项目概览|项目概览]]。
3. 按任务读取 [[project-memory/项目背景与当前边界|项目背景与当前边界]]、[[project-memory/开发与运维注意事项|开发与运维注意事项]] 或 [[project-memory/环境与部署|环境与部署]]。
4. 选择下方相关工作流，先读其绑定的任务计划书，再读取最近一篇工作记录。
5. 如果最近记录不足以解释当前状态、决策、阻塞或依赖，按时间由近到远继续查阅当前 checkout 中的相关历史和引用来源，信息足够后停止。
6. 按 [[project-memory/协议|项目记忆协议]] 核对当前代码、配置和变更规范后再继续。

## 可选：用 Obsidian 查看记忆图谱

如使用 Obsidian 可视化，将仓库根目录作为 Vault，以便访问项目记忆链接的源码、架构、OpenSpec 和仓库规则。全局关系图谱使用以下筛选，只展示可用于接管的项目记忆并排除模板：

```text
path:"project-memory/" -path:"project-memory/模板/"
```

推荐开启“仅显示已创建的笔记”和“箭头”，关闭“孤立文件”，并用颜色组区分 `首页.md`、`工作流/`、`工作记录/` 与其余稳定背景笔记。图谱是导航视图，不替代权威来源或实时核验。
