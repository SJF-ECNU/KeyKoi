# 开发与运维注意事项

- 实现前沿 [[AGENTS|项目入口]] 使用 CodeGraph 和 OpenSpec，按当前实现核对设计。P0 以 [[KeyKoi_Implementation_Plan_v0.1#16.2 P0 的工作包|草案的 P0 工作包]] 为起点。
- 设计中的授权绑定已认证会话、凭证、交付方式、登记目标和期限。工具名称、Agent 标签和请求自报身份只能提供元数据。管理权限和用钥权限分别授权。
- 设计要求凭证组合按同一版本读取和替换，入库前加密。配置、日志、命令行参数、模型上下文和测试材料禁止写入真实密钥。解密或授权失败时拒绝用钥，禁止回落到明文配置。
- 核对锁定、轮换、撤销和异常退出对缓存、受控连接、进程和临时文件的影响。验证记录注明工具、系统和适配器版本及测试范围。
- 联调按草案第 15 节使用生成的测试凭证和受控上游，记录认证或清理结果，不记录凭证原值。功能、兼容性和性能结论以实际运行证据为准。
- 请求内签名的工具（如阿里云 RPC 的 HMAC-SHA1 查询串签名）不能用 Header 网关替换认证，须走 `runtime_delivery`；不要把真实凭证写进工具普通配置来“兼容”这类工具。
- 阿里云 CLI 的 `~/.aliyun/config.json` 优先于环境变量；交付时必须用 `--config-path` 指向不存在的托管路径隔离旧配置，否则 KeyKoi 注入会被静默绕过。shim 的 `--prepend-arg` 已实现该隔离，并对用户自传同名参数报错。
- 通用解析接口 `/v1/resolve` 只交付 `runtime_delivery`；`sign` 许可的 SSH 材料走 `/v1/ssh-sign-material`（只含 `private_key` 与可选口令）。给新入口加取值路径时，先确认它属于哪一类，不要复用通用解析。
- 用钥决定只有一个来源：`keykoid` 内的 Broker。TLS 代理已改为经本机 IPC 请求授权，因此 `keykoi tls-proxy` 需要 keykoid 正在运行且密钥库已解锁；`--password-stdin` 保留但被忽略。数据库代理仍按 `runtime_delivery` 走 IPC。
- 数据库代理的上游传输默认 fail-closed：Redis/MySQL 上游要求可验证 TLS，明文上游必须显式 `--upstream-insecure`；MySQL 的 `--mysql-upstream-tls-mode verify-ca` 用于镜像自动生成的无 SAN 证书。
- 中心必须同时配置管理令牌与设备注册令牌（`--admin-token`、`--bootstrap-token` 或对应环境变量），二者相同会拒绝启动；非回环监听必须提供 `--tls-cert/--tls-key`。
- 通用 OAuth 客户端默认只接受 HTTPS 且禁止令牌交换跳转；受控回环测试要显式 `KEYKOI_OAUTH_ALLOW_LOOPBACK_HTTP=1`。
- 验收脚本里不测 Touch ID 的路径统一用 `grant add --auth permanent`；需要测策略时用 `biometric-auth.sh` 的参数化授权。
- 备份禁止写到运行库文件上；恢复会清空审计与接入状态并写一条说明。根密钥校验块随密钥库保存，恢复到另一套库后旧 Touch ID 登记会明确失败，需要重新登记。

- 中心策略的 `principal_id` 语义：给出时只授权该主体，省略时是绑定级策略（不限定主体）；许可记录调用方实际主体。中心的 `credential_id` 只是中心侧逻辑引用，各设备可有不同本地 ID，不参与拒绝；版本约束只在「本机领先于中心」时拒绝。
- 用钥许可要显式管理生命周期：网关每个请求申请并立即释放，元数据查询、协议签名与 SSH 签名材料在交付后释放，数据库代理在连接结束时撤销；Broker 自身按 `CleanupInterval` 周期性清理过期会话与许可，不要再加第二套定时器。
- 数据库代理的既有连接每秒最多做一次有界改绑检查（绑定状态、revision、上游目标）；判定变化时按协议先回错误再断开。检查失败（守护进程暂不可达）不断连，只记录并在下一轮重试。
- OAuth 提交必须走 `CommitCAS`（`store.ActivateVersionCAS` 全链路）；管理端停用/轮换 OAuth 凭证时会取同一把凭证级锁，不要绕过它直接改状态。

详见 [[KeyKoi_Implementation_Plan_v0.1|实施设计草案]] 第 4、5、12、14、15 节。
