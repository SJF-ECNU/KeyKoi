# 环境与部署

## 已核验的目录状态

2026-11-19 已有可构建的 Go 应用（模块 `keykoi`，Go 1.25），目录结构：

| 路径 | 职责 |
| --- | --- |
| `cmd/keykoi` | 管理 CLI、Helper、运行器、签名、SSH agent、数据库与 TLS 代理入口 |
| `cmd/keykoid` | 后台服务（单机与中心模式） |
| `cmd/keykoi-central` | 多设备中心服务（PostgreSQL） |
| `internal/vault`、`internal/store` | 应用层加密密钥库；SQLite 实现与内存实现 |
| `internal/broker` | 会话、Grant、UseLease 与用钥调度 |
| `internal/gateway`、`internal/runner`、`internal/helper` | 上游认证注入、受管理运行、原生 Helper |
| `internal/integration`、`adapters/` | 适配声明、探测、预览、应用、漂移与撤销 |
| `internal/osruntime`、`internal/ipcclient` | 本机 Unix socket、对端 UID 校验与 IPC 客户端 |
| `internal/central` | 多设备中心与设备客户端 |
| `internal/ssha`、`internal/signer`、`internal/oauth`、`internal/dbproxy`、`internal/tlsproxy` | P4 协议适配 |
| `web/` | 嵌入二进制的本机管理界面 |
| `tests/acceptance/`、`tests/fixtures/` | 可复测验收脚本与受控上游 |
| `packaging/macos/` | launchd 安装与卸载脚本 |

格式、静态检查与测试入口：`go build ./...`、`go test ./...`、`go vet ./...`。OpenSpec 文档校验 `openspec validate --changes --strict --no-interactive`。

## 本轮验收环境

所有验收在当前 Mac 的原生 macOS 运行。实际版本：macOS 27.0（26A5406e），arm64；Go 1.25.5；AWS CLI 2.41.0；aliyun-cli 3.5.3；PostgreSQL 18.6；OpenSSH_10.3p1。P3 的中心、PostgreSQL 与两个设备客户端在同一台 Mac 以独立进程与状态目录运行。结果见 [[docs/验收/验收总览|验收总览]]。Linux 文件隔离与 Windows 验收延期。

## 本机运行方式

2026-11-21 实测安装了 Go 1.26.11 构建的本地试用版 `d459739`。用户在服务重启后用主密码解锁，原有凭证、绑定和授权的标识保持一致。旧程序、启动配置与经校验的密文备份及 SQLite 副本见 [[openspec/changes/local-trial-upgrade/design#恢复入口|恢复入口]]。真实 Touch ID 验收使用临时保险库。

- 单机后台：`keykoid --data-dir DIR --gateway 127.0.0.1:8377 --admin 127.0.0.1:8378`（默认数据目录 `~/Library/Application Support/KeyKoi`）。首次使用先 `keykoi init`，之后 `keykoi unlock`。
- 本机 IPC：数据目录下 `keykoid.sock`（目录 0700、socket 0600，校验同用户 UID）。管理令牌在 `<数据目录>/admin.token`（0600）。
- 管理界面：只监听回环地址，校验 Host、Origin 与 `X-KeyKoi-CSRF`；管理 API 需要管理员令牌。
- 中心模式：`keykoi-central --dsn <PostgreSQL DSN> --admin-token <管理员令牌> --bootstrap-token <设备注册令牌>`（两者必须不同，非回环监听还要 `--tls-cert/--tls-key`），设备端 `keykoid --central http://127.0.0.1:PORT --central-bootstrap <令牌> --central-mode online|short_term`。设备身份保存在 `<数据目录>/device.json`（0600）。
- 安装：`packaging/macos/install.sh --prefix DIR [--label com.keykoi.keykoid] [--gateway ...] [--admin ...]`，卸载 `packaging/macos/uninstall.sh [--purge]`。
- 验收：`bash tests/acceptance/p0.sh` 等脚本，结果写入 `docs/验收/artifacts/<phase>/result.json`。
- 无感入口：`keykoi shim install --name <命令> --exe <真实绝对路径> --binding <binding> --env NAME=field:<字段> [--prepend-arg=--config-path --prepend-arg=<不存在的托管路径>] --update-shell`，之后直接执行原命令；`--prepend-arg` 用于隔离工具自带的明文配置文件（阿里云 CLI 的 `~/.aliyun/config.json` 优先于环境变量）；`keykoi shim list`、`keykoi shim remove --name <命令> --update-shell` 管理。shim 目录在 `<数据目录>/shims/`，安装记录 0600，只含引用与映射。
- 阿里云 CLI 通过运行时交付签名。已安装 shim 时，从 `keykoi shim list` 获取原工具路径，用于显式运行和本地配置检查。安装、配置隔离、停机与撤销见 [[docs/指南/工具接入与排障]]。

## 依赖与外部状态

- Go 依赖集中在 `go.mod`：`golang.org/x/crypto`（Argon2id、SSH）、`golang.org/x/sys`、`golang.org/x/term`、`modernc.org/sqlite`（纯 Go SQLite）、`github.com/jackc/pgx/v5`（PostgreSQL 与协议编解码）、`gopkg.in/yaml.v3`（适配声明）。
- 本机 PostgreSQL 18.6 由 Homebrew 管理（`brew services start postgresql@18`）。P3 与 P4 数据库代理验收各自创建临时数据库并在结束时清理。
- 预发布与生产环境、跨主机部署、主机名与端口分配、发布与回滚流程尚未登记；本轮只有本机拓扑证据。
