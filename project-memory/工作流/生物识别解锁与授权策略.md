# 生物识别解锁与授权策略

## 任务计划书

[[project-memory/任务计划/生物识别解锁与授权策略|任务计划书 · 生物识别解锁与授权策略]]。

## 当前状态

已实现 Touch ID 解锁密钥库与四种 Grant 授权策略（`once` 默认 / `window:N` / `per_use` / `permanent`），审计记录 `auth_method`（biometric/password/none）与 `auth_result`。验证状态只驻留内存，锁库、撤销、轮换、重启都会清空。

生物识别不可用或非 GUI 会话时回退一次性主密码证明；回退也不可用时返回 `AUTH_UNAVAILABLE` 明确拒绝。自动化验收用 `tests/fixtures/biometricstub` 作为助手替身，65/65 通过。

签名与看板登录已补齐：`packaging/macos/sign-biometric.sh` 会查 Apple Development / Developer ID 身份、渲染 `TEAMID` 前缀、用 `codesign --force --options runtime --entitlements` 签名并校验签名里含 `keychain-access-groups`；找不到身份时打印 Xcode / 团队 / Keychain Sharing 指引并退出码 2。`install.sh` 在 `KEYKOI_SIGN_BIOMETRIC=1` 时可选调用。`keykoi ui` 读 `admin.token` 打开 `http://<admin>/#token=<token>` 一键登录看板，页面读完立刻清除 hash。验收：`biometric-signing.sh` 21/21、`ui-login.sh` 30/30。

部署与续签已自动化：`packaging/macos/install-biometric-app.sh` 用 `security cms -D -i` 读 `.app` 内 `embedded.provisionprofile` 的 `ExpirationDate`，剩余 <2 天（`KEYKOI_BIOMETRIC_RENEW_DAYS` 可调）或描述文件缺失/读不出时才调 `build-biometric-app.sh --no-probe` 重建，再用 `ditto` 部署到 `<prefix>/KeyKoi Biometric.app` 并复校 `codesign --verify --strict` 与 `keychain-access-groups`；`--status` 打印到期时间/剩余天数/签名团队，`--deploy-only` 只部署不构建，全程不调用助手 `store/load/delete`，不碰 Keychain 条目。`packaging/macos/install-biometric-renew.sh` 生成并加载 LaunchAgent `com.keykoi.biometric-renew`（`StartCalendarInterval` 每周一次，默认周日 03:17，日志 `<prefix>/data/biometric-renew.log`），plist 显式写入 `HOME`/`PATH`/`DEVELOPER_DIR`/`KEYKOI_DEV_TEAM`，让 launchd 里的 `xcodebuild -allowProvisioningUpdates` 仍能读到登录钥匙串里的 Apple Development 身份；本机已加载，`next fire = 2026-11-22 03:17`，描述文件到期 `2026-11-26T17:13:46Z`。`install.sh` 默认部署 `.app`（`KEYKOI_BIOMETRIC_APP=0` 关闭）并把 `KEYKOI_BIOMETRIC_HELPER` 写进 keykoid 的 launchd 环境，部署失败只提示不中断。验收 `biometric-renewal.sh` 86/86。可选方案（付费账号 1 年描述文件、`-allowProvisioningUpdates` 自动续期、`LAContext` 弱化方案及其安全代价）写在 `docs/指南/生物识别助手续签与部署.md`。

生物识别助手已改成可持久的已签名 `.app`：`packaging/macos/biometric-app/` 是本机无 xcodegen 时用 `Tools/generate-xcodeproj.py` 确定性生成的 Xcode 工程，产物是 `KeyKoi Biometric.app`（`LSUIElement`，`Contents/MacOS/keykoi-biometric`，entitlements `$(AppIdentifierPrefix)com.keykoi.biometric`）。`build-biometric-app.sh` 用 `xcodebuild -allowProvisioningUpdates` + Team `977QNJU6V6` 自动签名，校验签名、`keychain-access-groups`、内嵌描述文件与启动探测，并把 `KEYKOI_BIOMETRIC_HELPER=<app>/Contents/MacOS/keykoi-biometric` 打印给 keykoi/keykoid。`vault.ResolveHelperPath` 接受裸二进制、`.app` 包或包内 `Contents/MacOS` 三种写法，keykoid 用它解析环境变量。真实 Keychain 的 `store/load` 因此变绿：`biometric-app.sh` 31/31，`launch_probe=ok`。

## 阻塞与下一步

裸二进制那条路已经不再是主路：`keychain-access-groups` 只在 `.app` + 内嵌描述文件下被系统接受，`sign-biometric.sh` 保留为诊断/回滚路径（本机仍会得到 `launch_probe=blocked-by-amfi` → `deploy=reverted`）。主路是 `build-biometric-app.sh`，本机已用 Xcode 已登录的 Apple ID（Personal Team `977QNJU6V6`）自动签发 `Mac Team Provisioning Profile: com.keykoi.biometric`，`launch_probe=ok`、`store/load` 往返通过。

仍等人工的一件事：在会弹指纹对话框的机器上确认一次 `keykoi vault enroll-biometric` → `keykoi unlock --biometric`（本机 `load` 在 5~25 秒内自动返回，没有出现需要人工点按的提示，所以自动化无法证明手势环节）。

续签侧的两点边界：① 描述文件仍在有效期内时 Xcode 复用旧文件，重建不会提前推进 `ExpirationDate`，只有过期或缺失才拿到新的 7 天窗口，所以「7 天」靠每周检查 + 临期重建兜住，要真正降频只有付费开发者账号（1 年）方案；② `install.sh` 已改成默认部署 `.app` 并写 `KEYKOI_BIOMETRIC_HELPER`，但运行中的 `com.keykoi.keykoid` 仍是旧 plist 拉起的，需要重跑一次 `install.sh` 才会生效（本次没有重启用户服务）。
