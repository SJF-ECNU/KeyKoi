# 审核缺陷修复设计

## Context

审核在 2026-11-20 对当前源码给出 15 项 P1 与 19 项 P2。共同根因是**决定与取值分处两个时刻**：授权在 T1 判定，凭证在 T2 读取，目标在 T3 使用，而中间没有把三者绑定到同一版本。修复不需要新抽象，只需要把「同一次授权返回的绑定、版本与主体」贯穿到交付点，并在交付点做最后一次提交前校验。

## Goals / Non-Goals

- 目标：消除越权取值、凭证送错目标、状态与权限不一致、恢复损坏和可远程触发的资源耗尽。
- 目标：修复后可被测试复现——每项缺陷至少有一个失败即报的用例或断言。
- 非目标：不引入统一策略引擎，不改命令名、路由名和配置字段；不重新设计中心拓扑。
- 非目标：不在本轮实现 Linux 文件隔离与 Windows 支持。

## Decisions

### D1 交付模式与字段可见性（01、07、33）

- `/v1/resolve` 只接受 `runtime_delivery`。`sign` 不再走通用解析。
- 新增受信接口 `POST /v1/ssh-sign-material`：要求 `sign` 授权 + `ssh_key` 凭证类型，只返回 `private_key` 与 `private_key_passphrase`，并立即从响应映射中清除引用。
- 中心许可申请携带主体、方式与凭证版本；Broker 以中心许可约束最终取值，而不是先取本机当前版本再交给中心判断。
- 签名器只在凭证自身是临时会话凭证（存在 `session_token` 字段且非空）时要求会话令牌，静态 AccessKey 仍按原样签名。

### D2 一次授权的原子性（02、04、19）

- `Authorize` 返回的 `Authorization` 增加绑定与凭证版本的快照；交付点只使用该快照，不再自行二次读取目标和凭证。
- 交付前重新校验：会话仍活跃、代次一致、授权仍 active、绑定 revision 未变、凭证 `current_version` 未变。任一变化返回稳定错误并撤销本次许可。
- 验证结果只在提交前的最后一次校验通过后写入缓存；写入时附带绑定的凭证版本，版本变化即视为未验证。
- 路由与许可的唯一性：同一 `upstream_origin` + 路径前缀的有效路由由存储层唯一约束；同一（主体、绑定、方式）只允许一个有效授权，新建时拒绝或替换既有项，选择规则由服务端决定。

### D3 代理的用钥决定归主服务（03、05、23、24、25）

- TLS 代理启动时不再自建 Broker；用钥决定通过本机 IPC 交给主服务，锁定、验证和中心策略统一生效。
- 转发使用授权返回的目标快照；既有连接在绑定 revision 变化时结束。
- Redis 上游默认要求 TLS（`redis+tls://` 或显式 `insecure_upstream: true` 才降级），MySQL 认证切换不使用未验证的上游 RSA 公钥。
- MySQL 从明文切 TLS 时把已预读字节交给 `tls.Conn`；Redis 与前端协商结果一致（只宣告真实支持的 RESP 版本）。
- 代理退出时限时排空：关闭监听器后取消活跃连接并给上游握手设截止时间。

### D4 恢复与根密钥（08、09、16、28）

- 备份禁止覆盖现有数据库文件；写入 `.tmp` 后 `fsync` + `rename`，并拒绝目标等于当前运行库。
- 恢复先完整校验（外层格式、条目完整性、能否用提供的口令解密），再在事务内替换；替换失败整体回滚。
- 每个密钥库保存独立的根密钥校验依据（`vault_id` + 校验块）；空库恢复后旧生物识别登记因校验块不匹配被拒绝，并提示重新登记。
- 轮换在一个事务内完成插入版本、切换 `current_version` 与更新到期时间。
- 恢复同步清除或保留审计与接入状态，二者口径一致并有审计记录。

### D5 中心与设备（06、26）

- 设备注册凭据与管理员凭据分离：注册令牌只能注册设备，管理操作要求管理员令牌或管理员会话。
- 中心监听默认回环；跨机器部署要求显式 TLS 配置，明文监听只允许回环绑定。
- 代次失效返回可区分的错误码，客户端只对「可安全重新申请」的代次做一次有界重试。

### D6 OAuth（10、11）

- 通用 OAuth 客户端默认 `https` 且校验证书；令牌交换的 HTTP 客户端 `CheckRedirect` 一律拒绝；令牌请求只在回环测试显式允许明文。
- 回调更新保留发起时记录的版本与状态：发起后管理员停用的记录不因回调而重新激活，版本不匹配时放弃更新。
- 管理端手工轮换、停用与 OAuth 回调共用凭证级锁；回调提交后的重新激活必须匹配刚提交的 revision。提交前复查失败按恢复状态处理，不能忽略读取错误后继续写。

### D7 接入与助手（12、21、30）

- 接入只备份本次受管字段的原始值，独立保存；撤销只还原这些字段，不动其他账号与助手既有设置。
- 含秘密的恢复材料加密保存。
- Git helper 与 `credential_process` 按各自命令行语法引用含空格的路径。
- 接入验证走实际运行路径（经中介解析并注入），并核对本次请求的用钥记录。

### D8 进程、路径与退出（13、15、22、29、34）

- Unix 监听先探测路径：连接成功说明 socket 存活则拒绝替换；连接被拒绝才清理残留。
- shim 与主 CLI 共用数据目录解析，安装目录下的 `data` 只在主 CLI 分支使用。
- 全局参数扫描在 `--` 处停止；运行器把子进程放到前台进程组；运行结果本身携带 `128+signal`，CLI 与 shim 不再接收 `ProcessState.ExitCode()` 的 -1。
- CLI 创建与轮换凭证时秘密字段支持隐藏输入或 stdin，不再只走命令行参数。
- 诊断测量请求不携带认证跨来源跳转。

### D9 网关与模型（27、31、34）

- 网关把验证失败映射为 401/403 + 稳定错误码，不再一律 500。
- 路径范围按规范化后的路径判定，与上游一致；响应读取区分 EOF 与中断，中断记为失败。

### D10 macOS 安装与生物识别（32）

- 安装前验证现有签名与描述文件；成功切换后再删除旧产物，状态检查失败即中止并传播退出码。
- 钥匙串重新登记先写带同一生物识别 ACL 的暂存项，读回并逐字节验证后通过 `SecItemUpdate` 原子替换正式项；不支持原子更新时安全失败，任何分支都不先删除正式旧项。

## Risks

- 05 的「上游强制 TLS」对现有明文测试上游不兼容：以显式 `insecure_upstream` 或测试专用配置保留，默认安全。
- 03 把代理用钥决定交给主服务会改变代理启动顺序（需要主服务可用）：以明确错误码和启动诊断替代静默降级。
- 19 的唯一约束可能拒绝既有重复数据：迁移时按「保留最新 active、把其余标为 superseded」收敛，并在审计中记录。
