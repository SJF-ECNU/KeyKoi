# 审核缺陷修复执行清单

验收依据为[需求场景](specs/credential-delivery-hardening/spec.md)，缺陷编号沿用[审核结论](../../../project-memory/任务计划/全项目代码与功能审核.md#审核结论)。每项的“证据”以当前源码、`go test` 或隔离验收输出为准。

## 1. 授权与交付边界（01、02、07、17、19）

- [x] 1.1 `/v1/resolve` 只接受 `runtime_delivery`，`sign` 走独立接口（01）。
- [x] 1.2 新增 `/v1/ssh-sign-material`，限定 `sign` 授权、`ssh_key` 类型与字段白名单（01）。
- [x] 1.3 `IPCProvider.ResolveMaterial` 改用签名材料接口（01）。
- [x] 1.4 交付前重新核对会话、代次、授权状态、绑定与凭证版本，失败即撤销许可（02）。
- [x] 1.5 验证缓存只在提交前校验通过后写入，并按绑定版本区分（02）。
- [x] 1.6 中心许可按主体、方式与版本申请，并约束最终取值（07）。
- [x] 1.7 `once` 预验证必须绑定具体会话，无会话预验证改为一次性交换（17）。
- [x] 1.8 同一（主体、绑定、方式）只允许一个有效授权，路由按目标唯一（19）。

## 2. 代理与上游传输（03、04、05、14、23、24、25）

- [x] 2.1 TLS 代理用钥决定交由主服务，不再自建独立 Broker（03）。
- [x] 2.2 TLS 与四种数据库代理按授权快照转发，绑定变更时重校验或结束连接（04）。
- [x] 2.3 Redis 上游默认要求 TLS，降级需显式配置（05）。
- [x] 2.4 MySQL 认证不使用未经验证的上游 RSA 公钥（05）。
- [x] 2.5 Redis 认证前请求解析设长度与嵌套上限（14）。
- [x] 2.6 MySQL 明文切 TLS 时移交已预读字节（23）。
- [x] 2.7 Redis 前端与上游协商同一 RESP 版本（24）。
- [x] 2.8 数据库代理退出限时排空，上游握手设截止时间（25）。

## 3. 密钥库、备份与恢复（08、09、16、28）

- [x] 3.1 备份禁止覆盖运行库，写临时文件后原子替换（08）。
- [x] 3.2 恢复先完整校验再事务替换（08）。
- [x] 3.3 密钥库保存独立根密钥校验依据，恢复后旧登记不再匹配（09）。

- [x] 3.5 备份与恢复的审计和接入状态口径一致（28）。

## 4. 中心与设备（06、26）
