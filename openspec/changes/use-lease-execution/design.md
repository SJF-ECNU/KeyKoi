# 用钥边界与执行许可

沿用 daemon、Vault、Broker 和三种交付方式。先让数据库连接持有原有 UseLease，统一检查会话、绑定、授权、凭证与绝对截止；代理间的故障只容许连接继续到原截止。让 TLS 代理使用调用方提供的会话，将密钥相关执行放到 daemon，连接目标从 daemon 读取。跨设备 Vault 和同用户 OS 隔离单列为部署决定。

执行步骤和结果见 [tasks.md](tasks.md)。

## 用钥结果与升级

| 授权方式 | IPC 或原工具能收到的结果 |
| --- | --- |
| `proxy` | HTTPS 或数据库的上游响应。启动代理的管理 IPC 只返回监听信息，执行留在 daemon。 |
| `sign` | SSH 与协议签名结果。 |
| `runtime_delivery` | 由 Binding 的 `runtime_fields` 限定的字段；旧绑定未配置该字段时沿用完整交付。 |

独立启动 HTTPS 或数据库监听器需要管理凭据，因为监听和信任配置由 daemon 执行。实际用钥按客户端提供的普通会话和 `proxy` Grant 决定。升级时为原代理用途添加 `proxy` Grant；旧的 `runtime_delivery` Grant 仍是有效的原始材料交付授权。HTTPS 的 Basic 代理密码是调用会话令牌，`--session-token-file` 可复用调用者的会话。代理诊断写入 daemon 日志。

管理者可在 `binding add` 用可重复的 `--runtime-field` 限定材料交付。IPC 配置空数组会禁止交付任何字段；更新绑定时省略字段会保留已有配置。历史备份仍可恢复。原始材料交付后由上游服务轮换或撤销。

数据库目标支持 `postgres://`、`redis://`、`rediss://`、`mysql://`、`mongodb://`，SSH 可登记 `ssh://`。数据库代理仍接受原有 HTTP 形式的绑定。原生地址只表达协议和地址，各协议的 TLS 兼容选项仍独立生效。

## 许可结束

Broker 在最后一次校验和登记许可之间持有同一把锁。代理执行持有已登记许可及绝对截止。锁库、关闭会话、撤销或替换授权、轮换或停用凭证均复用 Broker 的本地取消信号。数据库代理沿用有界定期复核绑定；在线中心确认针对原许可，短期离线模式最多用到原中心截止。复核失败后任何暂时失联都不会重置期限。HTTP 上游请求也受原许可取消和截止限制。

指定主机上的权威 Vault、多设备迁移与同用户执行隔离仍由部署场景决定。当前实现保留本地控制面及已有运行权限。
