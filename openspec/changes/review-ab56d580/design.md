# 修复 ab56d580 审查发现

目标是修复报告 K01–K14，并核对 C1–C3 对应的现有产品语义。步骤与验证证据统一记录在 [执行清单](tasks.md)。

- 协议层只在合法认证位置替换参数；默认使用经验证的上游传输。
- SSH Agent 保持原生协议，daemon IPC 只返回签名。TLS 代理用每实例随机令牌认证 CONNECT，将令牌写入仅当前用户可读的临时文件。
- Broker 用现有锁和授权代次提交许可及验证缓存。整库备份由同一存储视图读取，恢复与根密钥操作互斥。
- 中心以实际会话主体裁定，本机仍可继承账户授权。既有数据库连接的撤销范围按现有规范核对。

## 兼容行为

- TLS 代理启动时输出 `proxy_token_file=<路径>`。文件权限为 0600，代理正常退出时删除。客户端用标准 HTTP 代理 Basic 认证，用户名为 `keykoi`，密码从文件读取，CA 证书仍由客户端单独信任。
- PostgreSQL 上游默认使用 `require` 并校验证书链和主机名。受控的明文上游可显式使用 `disable`，`prefer` 是显式允许回落的兼容选项。OAuth token 端点默认要求 HTTPS，`KEYKOI_OAUTH_ALLOW_LOOPBACK_HTTP=1` 仅允许回环测试端点。
- SSH Agent 和 daemon 一起升级，签名 IPC 改用 `/v1/ssh-sign`。中心对实际会话主体执行主体限定，本机账户授权继承仍生效。
- Broker 的提交点是最终重校验后、持锁写入许可及验证缓存时。锁库和会话关闭使后续提交失败。已提交的使用可能仍在向外部工具或上游输出。
- 数据库连接在建立时申请用钥。锁库、会话过期和授权撤销影响新连接；现有连接在绑定改版、停用或退出代理时结束。许可到期不会主动切断已经建立的连接（C1）。
- TLS CONNECT 继续在返回成功前验证上游证书。取消独立预检会改变错误出现的阶段，作为单独的性能设计议题。
