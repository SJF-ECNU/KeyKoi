# 使用看板与按主体授权设计

工作流标识为 local-activity-and-subject-grants。执行步骤与证据见 [tasks.md](tasks.md)。

## Context

本机 socket 已校验对端 UID，Broker 已按主体和 Binding 查询 Grant；审计已保存用钥时间、主体、绑定、模式和结果。

## Decisions

- 原生 macOS 用内核给出的 IPC 对端 PID 与进程路径识别 Codex。优先选择进程链中距离调用最近的已登记 Agent。Codex App 和独立 CLI 各自匹配实际安装的可执行路径。客户端可查看主体，客户端自报的名字不参与匹配。此归属是同一 macOS 账户下的工作流识别，进程可访问的账户管理能力仍由原有边界决定。
- 代理各有持久主体 ID，先使用精确 Grant；账户级 Grant 可覆盖该账户下的代理，因而既有配置无需迁移。管理 UI 明示此范围。CLI 对同一组主体提供固定别名。
- 使用看板走本机受保护的管理接口。用已有审计记录构建近期视图，按时间倒序显示。只返回显示需要的结构化字段，区分钥匙放行与上游状态。对外历史记录保留原主体 ID。
- 发布验收使用本机 macOS 和独立临时数据目录。现有运行服务、密钥库和授权不参与验证。

- 管理员可通过 `POST /v1/subjects` 登记唯一标识、名称与绝对原生可执行文件。接口通过 kind 区分识别方式，本版为 native_executable。使用现有主体表持久保存规范路径，文件脚本和未登记的自报身份不会获得代理角色。
