# 使用看板与授权

在终端运行 `keykoi ui` 一键打开本机控制台。也可以查看 `keykoi status` 中的管理地址，默认是 `http://127.0.0.1:8378`。直接打开地址时，用数据目录中的管理令牌连接。

「使用记录」显示最近 500 条审计范围内的用钥事件，可按主体、方式和结果筛选。一次代理请求可能同时有授权放行和上游 HTTP 响应两条记录。

## 首次连接服务

1. 按页首提示初始化或解锁密钥库。可用的 Touch ID 和主密码入口在「设置」。
2. 在「密钥库」导入凭证，再点「新建绑定」，填写路由名称、目标地址和认证方式。
3. 从该绑定点「授权」，或到「访问授权」点「新建授权」，选主体、用钥方式与验证策略。

## 给自己或 Agent 授权

在「访问授权」中选择主体、已有凭证绑定和用钥方式，点击「添加授权」。主体包括当前 macOS 账户、Codex App、Codex CLI 和 Claude Code。想把本机账户显示为 Harry，可在启动守护进程时加 `--user-label Harry`。

账户级授权覆盖当前账户下的程序。只希望某个 Agent 用一个绑定时，给该 Agent 添加授权，并检查同一绑定和用钥方式下是否已有覆盖整个账户的授权。授权是在本机账户下按进程来源区分用钥路径，同一账户仍控制自己启动的进程。可在工具执行环境中运行 `keykoi whoami` 查看实际归属。从终端先执行 `keykoi run` 再启动 Agent 时，会话在子进程启动前创建，归属启动方。

```bash
keykoi grant subjects
keykoi grant add --principal me --binding <绑定ID> --mode proxy
keykoi grant add --principal claude-code --binding <绑定ID> --mode proxy
```

Codex App 和 Codex CLI 的标识分别为 `codex-app` 和 `codex-cli`。授权仅添加相应 Binding 和交付方式的许可。旧的主体 ID 仍可使用。

## 登记其他 Agent

在「访问授权」点「登记 Agent」，也可以通过 CLI 或受本机管理员保护的 `POST /v1/subjects` 发送 `key`、`label` 和 `executable` 三个字段。可选 `kind` 指定识别方式，目前支持且默认使用 `native_executable`。

```bash
keykoi grant register-agent --key my-agent --label "My Agent" \
  --executable /absolute/path/to/agent
keykoi grant add --principal my-agent --binding <绑定ID> --mode proxy
```

登记路径应指向 Agent 自己的 macOS 原生可执行文件。脚本、共享解释器和脱离了 Agent 进程链的调用需要单独设计接入。自定义目录升级后若二进制路径变动，按新路径和新标识登记并重设授权。Agent 进程名或请求里自报的标签不会决定身份。
