# 工具接入与排障

## 用 KeyKoi 接入阿里云 CLI

先把 AccessKey 导入 KeyKoi，为它创建绑定，并给调用主体授权 `runtime_delivery`。如果用的是 Homebrew 安装，在 `--exe` 中指定 `"$(brew --prefix aliyun-cli)/bin/aliyun"`。其他安装方式填写原工具的绝对路径。已经接入过时，可以用 `keykoi shim list` 查看登记的原始路径。接入后，`command -v aliyun` 通常会指向 KeyKoi 代理入口。

下面的例子假设绑定 ID 为 `bind_aliyun`，并使用默认 zsh 配置。将示例里的配置路径设为一个专供这次接入、尚不存在的文件。阿里云 CLI 的旧配置优先于环境变量，这个路径让受管调用使用 KeyKoi 交付的凭证。

```bash
ALIYUN_BIN="$(brew --prefix aliyun-cli)/bin/aliyun"
ALIYUN_ISOLATED_CONFIG="$HOME/.aliyun/keykoi.no-config.json"
keykoi shim install --name aliyun --exe "$ALIYUN_BIN" --binding bind_aliyun \
  --env ALIBABA_CLOUD_ACCESS_KEY_ID=field:access_id \
  --env ALIBABA_CLOUD_ACCESS_KEY_SECRET=field:access_secret \
  --prepend-arg=--config-path --prepend-arg="$ALIYUN_ISOLATED_CONFIG" \
  --update-shell
source ~/.zshrc
aliyun ecs DescribeRegions --region cn-hangzhou
```

如果凭证还包含阿里云 STS 会话令牌，在安装命令中加 `--env ALIBABA_CLOUD_SECURITY_TOKEN=field:session_token`。如果用 `keykoi run` 显式启动，也应使用原工具的绝对路径，并在工具参数中保留 `--config-path` 隔离。

## 停机期间查看版本和本地配置

受管命令连不上后台时，先用 `keykoi status` 检查当前数据目录对应的服务。服务可访问后，按状态提示解锁或检查授权。

`keykoi shim list` 在停机期间也可以列出原工具路径。若只是查看版本或检查工具原有的本地配置，把列表里 `aliyun ->` 后面的路径填入以下命令。

```bash
ALIYUN_BIN="/absolute/path/to/aliyun"
"$ALIYUN_BIN" version
"$ALIYUN_BIN" configure list
```

这两个原生命令由阿里云 CLI 直接运行。需要用 KeyKoi 凭证访问云服务时，恢复后台后继续用受管的 `aliyun …`。

## 撤销接入时遇到 CONFIG_DRIFT

报错会指出哪个文件的哪个区段和字段发生了变化。先保留手动设置，再把该字段恢复成 KeyKoi 上次写入的值，重新运行 `keykoi integration detach --profile <适配器ID>`。接入声明与工具安装路径自接入以来保持一致时，可以从 `keykoi integration plan --profile <适配器ID>` 查看 KeyKoi 的受管值。撤销只恢复接入前的受管字段，其他配置项保留。
