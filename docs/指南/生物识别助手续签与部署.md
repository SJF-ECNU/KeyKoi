# 生物识别助手部署与描述文件续签

[[docs/首页|返回文档首页]] · [[docs/索引/使用指南|使用指南索引]]

KeyKoi 的 Touch ID 助手以已签名的 `KeyKoi Biometric.app` 分发（见 [[docs/验收/验收总览|验收总览]] 的「生物识别助手签名 `.app` 包装」）。本页说明它为什么会在 7 天后失效、日常怎么部署、自动续签怎么工作，以及三种可选方案的取舍。

## 为什么需要续签

`keychain-access-groups` 是受限权限，只有 `.app` 内嵌描述文件（`Contents/embedded.provisionprofile`）才授权它。免费 Apple ID（Personal Team）签发的 `Mac Team Provisioning Profile` 有效期是 **7 天**：本机实测 `CreationDate 2026-11-19T17:13:46Z` → `ExpirationDate 2026-11-26T17:13:46Z`（UUID `c482a923-…`）。

到期后系统在启动阶段用同一个机制拒绝该助手（与 `packaging/macos/sign-biometric.sh` 里裸二进制被 AMFI 杀死一致），keykoid 会发现助手起不来并报 `AUTH_UNAVAILABLE`，用户回退主密码。

要点：**续签是重新签发**（向 Apple 取一份新的 `ExpirationDate`，或复用仍未过期的描述文件），不是给已有文件延期。因此自动化只能做「定期重建」，不能做「刷新时间戳」。

## 组件与文件位置

| 文件 | 职责 |
| --- | --- |
| `packaging/macos/build-biometric-app.sh` | `xcodebuild -allowProvisioningUpdates` 构建并签名 `.app`，校验签名/权限/描述文件/启动探测 |
| `packaging/macos/install-biometric-app.sh` | 部署与判断：读 `ExpirationDate`、剩余 <2 天或缺失时重建、复制到 `<prefix>/KeyKoi Biometric.app`、校验 `codesign --verify` 与 `keychain-access-groups` |
| `packaging/macos/install-biometric-renew.sh` | 生成/加载 LaunchAgent `com.keykoi.biometric-renew`，每周跑一次 `--build-if-needed`；支持卸载 |
| `packaging/macos/install.sh` | 安装主流程：默认部署 `.app`（`KEYKOI_BIOMETRIC_APP=0` 关闭），并把 `KEYKOI_BIOMETRIC_HELPER` 写进 keykoid 的 launchd 环境 |

部署后的路径（默认 prefix `~/Library/Application Support/KeyKoi`）：

| 项 | 路径 |
| --- | --- |
| app | `<prefix>/KeyKoi Biometric.app` |
| 助手可执行文件 | `<prefix>/KeyKoi Biometric.app/Contents/MacOS/keykoi-biometric` |
| 描述文件 | `<prefix>/KeyKoi Biometric.app/Contents/embedded.provisionprofile` |
| 续签日志 | `<prefix>/data/biometric-renew.log` |
| 续签代理 | `~/Library/LaunchAgents/com.keykoi.biometric-renew.plist` |

`install-biometric-app.sh` 只做「构建 → 复制 → 签名校验 → 报告」，**不调用**助手的 `store/load/delete`，不写、不改、不删任何 Keychain 条目。

## 手动使用

```bash
# 看状态：到期时间、剩余天数、签名团队、签名与权限校验
bash packaging/macos/install-biometric-app.sh --status

# 有构建产物就部署（不检查到期、不联网、不构建）
bash packaging/macos/install-biometric-app.sh --deploy-only

# 临期（<2 天）/缺失才重建并部署；这就是 LaunchAgent 每周跑的命令
bash packaging/macos/install-biometric-app.sh --build-if-needed

# 强制走一次重建（验收用来模拟临期，不真的等 7 天）
bash packaging/macos/install-biometric-app.sh --build-if-needed --force-expiry-check
```

`--status` 的机器可读输出（stdout，`key=value`）包含：`app`、`app_exists`、`helper`、`helper_env`、`signature_team`、`codesign_verify`、`entitlements_keychain_access_groups`、`profile_expiry`、`profile_expiry_epoch`、`remaining_seconds`、`remaining_days`、`min_days`、`renew_needed`、`renew_reason`。人读摘要同步打到 stderr。退出码 `0` 表示有效，`2` 表示需要动作（缺 app / 描述文件缺失或读不出 / 临期）。

## 自动续签机制

```bash
bash packaging/macos/install-biometric-renew.sh --install     # 写 plist 并 bootstrap
bash packaging/macos/install-biometric-renew.sh --status      # 是否加载、schedule、下次触发
bash packaging/macos/install-biometric-renew.sh --run-now      # 立刻触发一次并等收尾标记
bash packaging/macos/install-biometric-renew.sh --uninstall    # bootout 并删除 plist（保留日志）
```

- 调度：`StartCalendarInterval` = `Weekday 1 / Hour 3 / Minute 17`（每周日 03:17，可用 `--weekday/--hour/--minute` 改）。`RunAtLoad=false`，避免登录时额外跑一次构建。
- 命令：`/bin/bash <repo>/packaging/macos/install-biometric-app.sh --build-if-needed --prefix <prefix> --team 977QNJU6V6`。
- 日志：`StandardOutPath` / `StandardErrorPath` 都指向 `<prefix>/data/biometric-renew.log`（launchd 追加写）。
- plist 由 `python3 plistlib` 生成，写入后立刻 `plutil -lint`；加载走 `bootout → 轮询标签消失 → bootstrap`（`bootout` 是异步的，立刻 `bootstrap` 会得到 EIO）。
- **launchd 环境**：代理不加载 shell 启动文件，`HOME`/`PATH`/`DEVELOPER_DIR` 都可能缺失，而 `xcodebuild` 自动签名要读真实 `HOME` 下的登录钥匙串（Apple Development 身份）和 Xcode 账户缓存。因此 plist 的 `EnvironmentVariables` 显式写入 `HOME`、`PATH`（含 `<Xcode>/Contents/Developer/usr/bin`）、`DEVELOPER_DIR`、`KEYKOI_DEV_TEAM`、`KEYKOI_PREFIX`；`install-biometric-app.sh` 自身也会在 `HOME` 缺失时用 `dscl` 反查、在 `DEVELOPER_DIR` 缺失时用 `xcode-select -p` 兜底，并把 `-allowProvisioningUpdates` 交给 `build-biometric-app.sh`。
- 无人值守构建传 `--no-probe`：launchd 里没有 GUI 会话，`available` 会返回 unavailable；续签只依赖签名、权限、描述文件三项校验。

## 可选方案

### 方案 A：付费开发者账号（描述文件 1 年）

Apple Developer Program（99 USD/年）签发的开发描述文件有效期约 1 年，`com.keykoi.biometric` 的 App ID 与 Keychain Sharing 能力同样可用。

- 改动量：脚本不需要改；换团队后把 `--team`/`KEYKOI_DEV_TEAM` 指向新团队 ID，`--min-days` 阈值照旧（默认 2 天，也可以在到期前一个月把阈值调到 30 天做提前重建）。
- 收益：续签频率从「每周可能重建」降到「一年一次」，且不再受免费账号「同一时间只有有限个活跃描述文件」的约束。
- 代价：年费；需要把该账号的 Apple Development 证书装进登录钥匙串，并让 Xcode 登录该账号（自动签名仍依赖本机 Xcode 账户）。
- 建议：即便付费，也保留 LaunchAgent（成本为一次空跑，日志里能看到剩余天数），用来兜住证书吊销、App ID 能力被改、机器迁移这类意外。

### 方案 B：`xcodebuild -allowProvisioningUpdates` 自动续期

这条已经是默认路径：`build-biometric-app.sh` 带 `-allowProvisioningUpdates`，`CODE_SIGN_STYLE=Automatic`，团队由 `DEVELOPMENT_TEAM` 传入。只要描述文件仍有效，Xcode 会复用它；失效或临期时向 Apple 重新签发并在本机落盘。

- 前提：Xcode 已登录 Apple ID、团队可用、`com.keykoi.biometric` 勾了 Keychain Sharing、网络可达 `developer.apple.com`。
- 在自动化里跑（登录项 / CI / LaunchAgent）还要保证：进程能访问**登录**钥匙串（已解锁的 GUI 会话）、首次运行已接受 Xcode 许可、`HOME` 指向真实用户目录。
- 失败分类（脚本已实现）：`apple-id`（未登录/无证书）、`keychain-sharing`（能力未开）、`profile`（无可用描述文件）、`network`（拿不到 Apple 服务）。每类都会打印对应的人工步骤，验收把它记成 manual 而不是失败。
- 注意：自动续期解决的是「重新签发」，不解决「7 天太短」；要真正降频只有方案 A。

### 方案 C（弱化，不默认启用）：不用 Keychain ACL，仅用 LAContext 当门禁

思路：根密钥不再以 `biometryCurrentSet` ACL 存进 Keychain，而是用主密码派生的 KEK 加密后落普通文件；`unlock` 前调用 `LAContext.evaluatePolicy(.deviceOwnerAuthenticationWithBiometrics)`，通过就放行。

安全代价（这是不默认启用的原因）：

- LAContext 的结果只证明「**本进程**刚问过系统」，不绑定到密钥材料。同一用户下的任何进程（含恶意软件、注入到 keykoid 的代码）都可以跳过门禁直接读文件解密。
- 失去 `biometryCurrentSet` 的语义：新增或删除指纹后旧密钥**不会**失效，丢失的设备上被登记的指纹仍能解锁。
- 失去「系统在密钥释放那一刻做校验」的保证：验证与使用之间可以被 replay。
- 磁盘镜像、Time Machine 备份、`data/` 目录被盗时，攻击面从「系统托管的 ACL 条目」变成「一个文件 + 用户口令」。
- 因此本方案只适合无 Touch ID 的 CI、排障、演示环境；生产默认仍是 `.app` + `keychain-access-groups` + 每周续签。启用它需要改 Go 业务代码（`internal/vault` 的根密钥存取路径），不在打包脚本范围内。

## 排障

| 现象 | 检查 |
| --- | --- |
| `--status` 报 `renew_needed=yes`，`renew_reason=expiring` | 正常，等 LaunchAgent 或手动 `--build-if-needed` |
| `renew_reason=profile-missing` | `.app` 里没有 `embedded.provisionprofile`，手动重建 |
| 构建退出码 2 / `failure_class=apple-id` | Xcode → Settings… → Accounts 登录 Apple ID，`Manage Certificates…` 生成 Apple Development |
| `failure_class=keychain-sharing` | developer.apple.com → Identifiers → `com.keykoi.biometric` 勾 Keychain Sharing |
| `failure_class=network` | 代理/网络不可达 `developer.apple.com`；离线时只有方案 C 能绕过 |
| LaunchAgent 加载失败 | `cat <prefix>/data/biometric-renew.bootstrap.err`；`launchctl print gui/$(id -u)/com.keykoi.biometric-renew` |
| 续签日志一直没更新 | `launchctl print` 看 `last exit status`；确认 plist 里 `HOME` 是真实用户目录 |
| 助手启动被系统杀死 | `log show --last 5m --predicate 'eventMessage CONTAINS "keykoi-biometric"'`；多半是描述文件过期 |
