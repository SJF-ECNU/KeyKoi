# 把服务接入模型 API

适用：Agent 或后端服务在自己的进程里调用模型 API（OpenAI / Anthropic / 兼容网关），希望密钥不进入代码、配置、日志和模型上下文。

## 推荐方式：服务只拿会话令牌（proxy 模式）

服务不需要真实 key，只要把模型的 `base_url` 指向本机网关，把「API Key」位置填成 KeyKoi 会话令牌。启动器负责注入这两个值：

```bash
# 1) 录入一次真实 key
#    只写字段名，值用隐藏输入（终端不回显）或 stdin 读取，避免进入 shell 历史与进程参数。
keykoi credential add --kind api_key --label "model prod" --field token
#    脚本里也可以这样：printf '%s\n' "$KEY" | keykoi credential add --kind api_key --label "model prod" --field token --field-stdin

# 2) 登记目标：origin 固定，路径按需收窄
keykoi binding add --id bind_model_prod --credential <cred-id> \
  --origin https://api.openai.com --route model-prod --scheme bearer \
  --paths /v1/chat/completions,/v1/embeddings

# 3) 给本机用户发 proxy 许可（不需要 runtime_delivery）
keykoi grant add --principal "principal_local_$(id -u)" \
  --binding bind_model_prod --mode proxy --max-lease-seconds 300

# 4) 用受管理启动器启动服务
keykoi run --mode proxy --route model-prod --exe "$(command -v python3)" \
  --session-ttl 8h \
  --env OPENAI_API_KEY=runtime:session_token \
  --env OPENAI_BASE_URL=runtime:gateway_route \
  -- app.py
```

- `runtime:session_token`：中介会话令牌（`kks_…`），不是真实 key，只对 KeyKoi 有效、可到期、可撤销。
- `runtime:gateway_route`：`http://127.0.0.1:<网关端口>/gateway/model-prod`，SDK 会自己在后面拼 `/v1/...`。
- 服务进程及其子进程**看不到真实 key**；网关在转发时才注入，并在审计里只记元数据。

## 服务里的代码不用改

以 OpenAI Python SDK 为例，代码仍然是：

```python
from openai import OpenAI
client = OpenAI()  # 读取 OPENAI_API_KEY 与 OPENAI_BASE_URL
resp = client.chat.completions.create(model="gpt-4o-mini", messages=[{"role": "user", "content": "hi"}])
```

Anthropic SDK 同理，把 `base_url` 指向 `/gateway/<route>`，`api_key` 用会话令牌即可；网关会把它从 `x-api-key` 位置移除并换成真实 key。

## 生命周期与限制

| 项 | 当前行为 |
| --- | --- |
| 会话有效期 | 默认 12 小时，可用 `--session-ttl` 指定，最大 24 小时 |
| 服务重启 | 重新经 `keykoi run` 启动即可获得新令牌；旧令牌在后台重启或锁定时失效 |
| 锁定 | `keykoi lock` 立即停止新的用钥；运行中的服务会收到 503 |
| 部署位置 | 目前只支持服务与 KeyKoi 同机（网关只听回环、IPC 走 Unix socket）；跨主机需中心模式，尚未提供网关远程接入 |
| 密钥轮换 | `keykoi credential rotate` 后，新请求使用新版本；旧许可与缓存失效 |
| 撤销 | `keykoi grant revoke` 或停用凭证后，下一次请求即失败 |

## 常见错误语义

- `401 SESSION_INVALID`：会话令牌缺失、过期或后台重启过（重启后需重新启动服务）。
- `403 USE_NOT_ALLOWED`：没有对应 proxy 许可，或请求的路径不在该 Binding 的允许列表。
- `404 BINDING_DISABLED`：路由未登记、Binding 停用或路径越界。
- `503 VAULT_LOCKED` / `CONTROL_UNAVAILABLE`：密钥库锁定或中心不可用，新用钥被停止。

## 什么时候才用 runtime 模式

只有服务必须自己持有真实 key 时（例如它自己算请求签名，或只能通过环境变量给自家 SDK 传 AK/SK），才用 `keykoi run` 的默认 `runtime` 模式或 PATH shim。这会明确把真实值交给该进程及其后代，属于「运行时交付」，安全边界与 proxy 模式不同。

## 远程/容器部署

当前版本没有把网关暴露到网络的能力（这是有意的默认）。服务与 KeyKoi 需要同机部署；容器化时把 KeyKoi 与业务进程放在同一容器/同一网络命名空间的回环接口上。多主机场景依赖 P3 中心模式，中心目前只发放许可，不转发模型流量。
